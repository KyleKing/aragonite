# aragonite

Shared Go packages for kyleking's terminal tools. Aragonite is the mineral coral
skeletons are built from, which puts it alongside calcipy and corallium.

Extracted from [gh-repo-dashboard](https://github.com/KyleKing/gh-repo-dashboard) rather
than designed up front, so every package here has at least one real consumer.

The data packages hold data and predicates only. The rendering packages under `display`
and `tui/` take their styles as an argument and carry no vocabulary of their own, so a
consumer keeps naming its own colors and styles while sharing the layout, wrapping, and
measurement underneath. [DESIGN.md](DESIGN.md) has the layering rule in full.

## Packages

| Package | What it holds |
| --- | --- |
| `cache` | Generic TTL cache with a disk store, a registry for package-level caches, and remote-scoped keys so parallel checkouts of one remote share a read. `PersistedStale` returns the last disk value with its age past the TTL, for drawing at once while a refresh runs |
| `display` | `forge` and `vcs` models as plain text: relative times, status summaries, review glyphs, and the em-dash placeholder. Importing both is what keeps `forge` and `vcs` from importing each other |
| `forge` | The pull request model shared by every tool that reads a code host: `PullRequest`, its detail and preview forms, checks, and workflow runs |
| `fuzzy` | How well a typed query matches a line as an in-order subsequence, for a palette, a finder, or a legend filter: runs of adjacent letters, word starts (camel humps included), and the query's own case score more, an early match beats a late one, and the best placement is found rather than the leftmost. `Score` answers the rune positions for highlighting, and `Rank` keeps and orders any slice by a text function, ties in input order. Lifted from jj-diff's finder |
| `generated` | Whether a path names a machine-written file (lockfiles, `vendor/`, `node_modules/`, `.pb.go`, snapshots), from suffix and directory patterns a caller can add to, so a diff folds the file and reports its size |
| `ghcassette` | Records and replays `gh` subprocess calls through a stand-in binary on PATH, so a test replays the bytes GitHub sent in the shape gh prints them. The subprocess counterpart to `transport` |
| `forge/github` | GitHub through the `gh` CLI: pull requests, reviews, comments, search, Actions runs (by ID, by query, and the latest per workflow on a ref) with their jobs and step timings, `ListRunTimings` (runs with head SHA, actor, attempt, and pull requests, read a day at a time to stay under the API's 1000-result cap) and `RunJobTimings` (runner labels and step times) for timing analysis, `MergeQueueEvents` (queue joins, removals with reasons, and merges, which only GraphQL exposes), and the caches typed on them. `WithRunner` puts a consumer's own executor behind every call, which is how a tool keeps its own recording seam or mutation guard. `Budgets` reads what is left of the hourly allowances, one per pool, since core, GraphQL, and search are separate and a tool out of one can still make the other's calls; the read is free, so a burst can ask whether it is affordable rather than firing and reporting the wreckage. A second host is a sibling directory, not a rename |
| `highlight` | Source lexed into byte-range spans in 14 classes (chroma underneath), with no colors, so the caller picks them. `Lines` lexes a file's lines as one unit and picks the grammar by file name alone, `Tagged` by a fence's language tag, and `Cache` lexes each side of a diff's file whole the first time one of its lines is asked for, so multi-line strings and comments classify correctly and a frame costs a lookup. `Cache.Start` lexes a file in the background and `Peek` answers without ever lexing, so a screen can draw plain text first and redraw in color when the spans land. The grammar each file name resolves to is remembered, since resolving it walks every lexer's globs |
| `keyusage` | Logs a tool's command keys per context, and its CLI subcommands and flag names (never their values), to `~/Sync/.<app>/usage` (off without it) and reads them back against the tool's bindings: keys never used, keys gone stale, keys pressed with nothing bound, and keys that mean different things on different screens. `Level` feeds `keyhint.Hint.Fresh` so a legend brightens a key more the longer it goes unused (7, 14, 28 days). See [docs/keyusage.md](docs/keyusage.md) |
| `ratelimit` | GitHub's hourly allowances enforced on an `http.RoundTripper`: an exhausted pool becomes a typed error naming when it returns, and further requests to that pool fail without spending one to relearn it. Blocks per pool, since core, GraphQL, and search are separate allowances and being out of one leaves the others usable. The reactive half of `forge/github.Budgets`: ask that before a burst, get this when one runs out anyway. Auth is left to whatever builds the client, because go-gh already resolves the gh CLI token with a `GITHUB_TOKEN` fallback and wrapping that would buy nothing |
| `stats` | Percentile (linear interpolation, on a copy) and mean over float64 samples, for the timing tables tools repeat |
| `trail` | A tool's command log: every external command it ran (jj, git, gh) with whether it wrote, how long it took, its exit, and its stderr in full, in a bounded ring safe for commands run off the update loop. `Run` runs and records, `Start`/`Done` time a call the tool runs itself, `Shell` quotes argv into a pasteable line, `Echo` is the status line that teaches a write's command (`squashed into rnzx · jj squash --from wkwy --into rnzx · u undo`), and `Lines` draws the log for a `gm` list with each failure's stderr under it. Session data only, never written to disk |
| `transport` | A test seam and mutation guard for an `http.RoundTripper`-based API client: register a fake transport in tests, or get a guard that panics on a real mutating request when none is registered |
| `tui/box` | Content in a bordered rectangle of exactly the width and height given: lines past the inner height are dropped and lines past the inner width are cut with an ellipsis, so a pane never loses its bottom border to a wrapped line. The focused and idle faces each carry their own border |
| `tui/card` | A block drawn inline in a list or a pane, with a rounded border named on top and captioned below. The inline sibling of `overlay.Box`, which centers a scrolling box over a frame |
| `tui/coach` | What to do next, and what the reader is not using that would help. A tool writes `Rule`s over its own state type and `Next`/`All` rank the ones that hold (do, then next, then could), skipping any whose action the `keys.Gate` refuses. `Repeat`, `Instead`, and `ViaPalette` detectors watch the action stream for the long way round, and a pool of unlearned-key tips stands by, checked against the ledger and optionally the keyusage log. `Tip` is rate limited (one at a time, none in the first minute, idle only, at most one per ten minutes and four per session, three days per tip, retired once used or after three showings untaken) and any key clears it. The `Ledger` is an always-on local file at `$XDG_STATE_HOME/<app>/coach.json` holding tip history and recent commands (it satisfies `palette.Seen`), separate from the opt-in usage log. `Line` and `TipLine` draw the inline layout (status line and footer slot), `BandLines` the opt-in labeled band, and `Mark` brightens the footer key a suggestion names |
| `tui/commandbar` | The registry behind a `:command` bar, generic over the screen's model, and the tab completion that reads it. `Lookup` resolves an exact name or the one command a prefix leaves, `Completions` asks the command for the argument being typed, `CommonPrefix` is how far one tab press fills in without choosing, and `ReplaceLastWord` swaps the word under the cursor. It owns no input widget and draws nothing |
| `tui/empty` | The card a screen shows where it has nothing to list: what is empty on the top edge, why and what would fill it inside, then the keys out drawn bare. `Card` centers it in a list's whole body and `Block` is the card alone. The same card is a tool's first-run welcome |
| `tui/frame` | The shell around a screen's body: a header with the title, facts, and tabs with count chips, then the body padded to fill, an optional panel about the row under the cursor, and a footer pinned to the last row. `Strip` puts the tabs after the title over a rule that underlines the active one. Its status message takes room from the hints rather than covering a key, yields to hints marked `Pin`, and is cut at a word with an ellipsis, and `BodyRow` and `TabAt` say what a click landed on |
| `tui/handoff` | Hands the terminal to another program and takes it back: a `sh -c` template with `{path}`-style placeholders, each value shell-quoted so a branch name cannot inject a command, run under `tea.ExecProcess` in a directory, answering with a `DoneMsg` so the caller can redraw and refresh. An unknown or empty placeholder is an error, and `Needs` lists the keys a template uses so a screen offers a hand-off only where its values exist |
| `tui/icons` | The glyphs drawn beside files, folders, threads, and states, in a Nerd Font set (the default) and a unicode set for a terminal without a patched font. `Resolve` reads an `ARAGONITE_ICONS` override, then the tool's own setting. Every glyph is one cell in both sets, so switching never moves a column |
| `tui/keyhint` | The keys a screen offers, bracketed inside the word they do (`[p]ost one`, `[tab] switch`) so a footer needs no legend. The same shape captions the second key of a chord while it waits, `Fit` sheds the lowest-priority hints until a footer fits (a `Pin` hint such as help or quit goes last) and draws the ones that do not apply dimmed, `Help` lays out the full legend with the keys right-aligned in one column, and `Panel` draws a prefix key's next keys as a bordered block with applied entries in the accent and a right-aligned count, for `overlay.BottomRight` to float over a screen |
| `tui/keys` | The key vocabulary jojo, jj-diff, and second-look share, as data: every binding is an action name, its key sequences, a description, and a legend group. `Global` and `DiffView` hold the shared table (the `]`/`[` motions over `Objects`, the `z` fold page, the `\` view page), `Flags` the `-x` picker toggles spelled as jj spells them, and `Merge` joins it with a tool's own verbs and a user's rebinds, refusing any key two actions would share. A `Matcher` turns presses into actions and reports a waiting prefix for `keyhint.Panel`, `Motion` makes `n`/`N` repeat the last motion, and `Disagreements` is what each tool's `TestKeymap_AgreesWithShared` checks. A `Gate` answers whether an action can run where the cursor is and why not (`Availability{OK, Why}`), and `HintsAt` and `LegendAt` mark what it refuses `Off` with the reason, so a key is never a silent no-op: the legend says why and a press can say it in the status line |
| `tui/markdown` | Markdown and raw HTML flattened to terminal lines, folding `<details>` to its summary so a bot's changelog costs one line |
| `tui/overlay` | A block centered over a frame as one unit rather than line by line. `Over` draws it on the live frame with everything around it stripped of its styling and dimmed, `Box` and `Blit` float a scrolling box or any block at a cell, and `BottomRight` anchors one to the corner |
| `tui/skin` | The faces every screen here draws with, built from a palette and the one accent that tells a tool from its siblings, so a title looks like a title in each of them. `Selection` is the one face for the row under the cursor: a quiet tint, or reverse video under `NO_COLOR`. `Rule` draws a section heading as a labelled rule, `FileBand` lifts a file's header row off the frame, and `Diff` gives the wash, mark, and sign-bar faces a changed line is drawn with |
| `tui/split` | Where a screen's detail region goes at a given size: beside the main block behind a one-cell rule from a width, beneath it when the reader opened it, nowhere when there is no room. `Place` picks, and `Render` takes both blocks as `func(width, height)` renderers and joins them into exact-size lines, so a caller draws once at the final width |
| `tui/overview` | The track on a frame's right edge: the thumb says how much is on screen and where, and typed marks say what waits off screen at each height (a change, something to act on, a draft, a handled row). A higher `Rank` wins a shared cell and the thumb wins over any mark. Content that fits draws no track |
| `tui/pen` | A lipgloss style drawn without running lipgloss's renderer per call. `Of` learns the style's escape sequence once, and `Render`, `Write`, and `Spaces` then draw a run byte for byte as `Style.Render` would, about twenty times faster. A style with a width, padding, a border, a transform, or a link, and any text holding a line break, falls back to `Render`, so a pen is never wrong |
| `tui/palette` | The one place a reader finds anything a screen can do. `:` opens it in `Run` mode (typing searches, Enter runs) and `?` in `Browse` mode, the legend, where a key press explains that key instead of running it, `/` filters, and Enter runs. Entries come from a `keys.Keymap` and its `Gate` (`FromKeymap`, taught by an `About` per action: the command it runs, flags, git-word aliases, prose, related keys) or from a legend tree (`FromLegend`), and `WithSeen` adds recent runs and counts. `Rank` lists here first, then recent, then off here with the reason, and a query ranks by `fuzzy` over the description, action, key, command, and aliases. It draws as a drawer with an explainer pane (`Note`) from 100 columns and a strip over the bottom rows below, and answers `RunMsg`, `RefusedMsg`, or `ClosedMsg` |
| `tui/region` | The block a list opens beneath itself: a rule, label/value facts, a body, and a captioned divider. `Render` fills a fixed height, and `Lines` takes the height as a ceiling and draws only what the region holds |
| `tui/table` | Fits columns to an available width and pads cells to it, measuring in display cells so wide glyphs never shift a row. `Row` paints the gutters in the row's own face, so a selected row has no gaps. `ScrollWindow` picks the rows of a list a viewport shows so the selection stays visible |
| `tui/theme` | Catppuccin Latte and Macchiato palettes and the Ink palette, terminal-background detection with a `CATPPUCCIN_THEME` override, an eight-role semantic view over a palette, and `Tint` and `Mix` for blending two colors |
| `vcs` | git and jj behind one interface, with the working-tree summary, branches, commits, stashes, worktrees, diff, checkout identity, and stamp |

Two open questions: how far to go before the missing key is worse than no modes at all (counts, registers, and `/` are where the subset starts lying), and whether the honest answer is to hand the buffer to the user's own `nvim` in a small pane the way Claude Code's ctrl+g does, which costs nothing to learn and gets their real config |

that is not a git tool needs them.

## Local development

Consumers use a `go.work` pointing at a sibling checkout, so nothing has to be published
to iterate across repos. `go.work` is gitignored.

```sh
cd second-look && go work init . ../aragonite
```

[docs/extraction.md](docs/extraction.md) records what the first extraction taught, so the
next one costs less.
